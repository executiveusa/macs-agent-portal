# Agent MAXX Business Plan

## North Star

Help MACS and its partners move the business outcome closest to money with less owner complexity.

Agent MAXX is the interaction surface. The canonical commercial reasoning, client context, approvals, reusable skills, and experiment rules live in `executiveusa/maxx-migrations-agentic-systems`.

## Public commercial model

There are exactly four client-facing buckets:

1. **Reset** — recover value already leaking through broken, scattered, slow, or confusing systems.
2. **Momentum** — turn a working offer into steadier qualified attention and follow-up.
3. **Scale** — the idea is working; grow without complexity.
4. **Launch** — prove demand for something new with the smallest credible launch.

No fifth public bucket is allowed without an explicit architecture decision in the canonical backend.

Internal labels such as Client Zero, Built Here, labs, tools, products, or R&D are evidence/capability labels only.

## Commercial operating rule

For every meaningful business request, determine:

- current condition
- primary bucket
- desired outcome
- problem closest to money
- primary metric
- primary CTA / next action
- evidence available
- approval required

Then call or load the canonical backend growth model rather than duplicating it in this portal.

## Priority

Work in this order unless the owner explicitly changes it:

1. fix revenue-blocking or trust-blocking leaks
2. improve conversion of existing attention
3. exploit existing customers, relationships, proof, and channels
4. make a working process repeatable
5. increase volume
6. add new channels or complexity only after the existing path is measured

## Success metrics

Prefer commercial evidence in this order:

1. cash / gross profit
2. closed sales
3. qualified pipeline
4. engaged leads / booked calls
5. conversion behavior
6. retention / repeat use
7. owner time saved
8. attention metrics

Do not declare a commercial win from impressions, followers, views, or generic engagement alone.

## Portal responsibilities

The portal should make it easy for Stacy/team to:

- say what matters in plain language
- see which bucket the work belongs to
- see the next recommended move
- approve consequential actions
- review experiments and proof
- understand what changed and why
- avoid learning backend implementation details

## Backend responsibilities

The backend owns:

- `docs/icm/MONEY_MODELS.md`
- `icm/growth-engine/SKILL.md`
- Reset / Momentum / Scale / Launch agent skills
- experiment templates and evidence rules
- durable client context
- approval semantics
- commercial routing and reusable operating doctrine

## Release rule

Before shipping a growth feature in this portal, verify that it advances one of the four buckets, calls/reuses the backend authority rather than forking it, and produces evidence that can be reviewed by the owner.
