# MAXX ICM federation

## Rule

Do not create a second business brain inside Hermes. The canonical business/ICM backend is `executiveusa/maxx-migrations-agentic-systems`.

Use the `maxx-control-plane` MCP tools:

- `maxx_migrations_health`
- `maxx_migrations_manifest`
- `maxx_migrations_route`

## When to call

Call the manifest when you need repository ownership, evidence states, the motion gate, or the supported machine surfaces.

Call route when a business condition must be classified into one of the only four public buckets: Reset, Momentum, Scale, Launch.

Call health before relying on the backend in a consequential mission or when a prior call failed.

## Evidence rule

A response proves only that specific call. Do not call the three-repository system `VERIFIED` until the canonical walk-test motion path has current deployed-runtime evidence.

If the backend is unavailable/degraded, report that state and continue only with context whose authority is already established locally. Never invent a canonical answer.

## Security

Hermes never receives `MAXX_MIGRATIONS_API_KEY`. The scoped Hermes MCP credential reaches the control plane; the control plane owns the backend credential and policy.
